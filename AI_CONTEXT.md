# AI_CONTEXT — передача проекта CLIP AI Studio следующему ChatGPT / разработчику

> Прочитай этот файл целиком перед тем, как менять проект. Это handoff-контекст, а не обещание, что все задуманные функции уже реализованы. Сверяй каждое утверждение с `app.py` и тестируй изменения.

## 1. Цель проекта

Развивается локальное приложение **CLIP AI Studio**, бренд **Premium Violet · By Senya**. Пользователь хочет удобную программу для нарезки длинных видео и стримов на короткие ролики (Shorts/Reels/TikTok), с аккуратным премиальным тёмно-фиолетовым интерфейсом, понятными статусами, прогрессом и простым запуском на Windows.

Пользователь не хочет получать абстрактные советы вместо результата: при запросе на изменение приложения нужно работать с текущим исходным кодом, сохранять существующие возможности и данные, проверять синтаксис/запуск, собирать готовый ZIP или выдавать конкретные файлы и пошаговую инструкцию.

## 2. Текущее состояние и версия

Этот репозиторий подготовлен из исходника **CLIP AI v21 — Twitch Clipper**. Основной файл — `app.py` (Streamlit). Источник комплекта — архив `CLIP_AI_v21_Twitch_Clipper.zip`.

В истории версий в предыдущих итерациях были v12–v21: улучшения навигации и внешнего вида, создание студии, мультиплатформенный источник через yt-dlp, редактор Shorts, модели OpenAI, улучшения прогресса и Twitch Clipper. В этом репозитории лежит только текущий исходник v21, а не полная Git-история всех этих архивов. Не утверждай, что история релизов/все промежуточные ветки присутствуют в Git, если их туда отдельно не добавили.

## 3. Технологии и запуск

- Python 3.11 x64 рекомендуется.
- UI/backend: Streamlit.
- Видео: FFmpeg через `imageio-ffmpeg`.
- Распознавание речи: `faster-whisper` (локально, CPU/int8 в интерфейсе/описании настроек).
- Скачивание поддерживаемых ссылок: `yt-dlp`.
- Twitch LIVE chat: Python standard library (`socket`, `ssl`, `threading`) через Twitch IRC.
- AI semantic ranking: OpenAI API, если пользователь сам вводит API key и имеет API-доступ.
- Основной запуск: `streamlit run app.py`, в Windows для пользователя — `START_CLIP_AI.bat`.
- URL локального интерфейса по умолчанию: `http://localhost:8501`.

Это локальное приложение, а не уже опубликованный публичный сайт. Браузер является интерфейсом; Python/Streamlit-процесс выполняется на компьютере. Репозиторий GitHub — это исходный код, не хостинг приложения. Для использования на другом компьютере нужно установить Python и зависимости. Данные пользователей не синхронизируются автоматически между копиями.

По навигации `app.py` содержит:

Основная обработка видео включает загрузку файла/URL, распознавание речи, подбор кандидатов в клипы, опциональное ранжирование через OpenAI, оформление/субтитры и экспорт. Поддержка URL зависит от фактических возможностей `yt-dlp` и ограничений конкретного сайта.

Не обещай, что приложение может скачать абсолютно любое видео с любого сайта: приватные, DRM-защищённые, геоблокированные, авторизованные и изменившие API источники могут не работать.

## 5. Twitch Clipper — как работает сейчас

В `app.py` ищи раздел `Twitch Clipper: chat ingestion, ranking and local export` и функцию `render_twitch_clipper_page()`.

### LIVE

- Вводится Twitch-канал/URL.
- Подключение к чату через OAuth token со scope `chat:read`; есть best-effort anonymous режим.
- Указывается логин Twitch.
- Поле Client ID используется для нативного создания Twitch Clips.
- Можно указать текущий offset VOD, если мониторинг запущен не с начала стрима.
- Чат читается через TLS/IRC, сообщения и таймкоды сохраняются локально в JSONL.
- Отслеживаются всплески сообщений за короткие окна; пользователь видит последние сообщения, счётчики и предупреждение о всплеске.
- Есть ручная отметка момента.
- Есть кнопка скачать лог чата.
- Опциональное создание нативного Twitch Clip требует token scope `clips:edit` и соответствующий Client ID.

**Критическое ограничение:** LIVE режим только наблюдает чат/таймкоды. Он не записывает видео. Нельзя говорить пользователю, что в фоне идёт запись всего стрима или что он уже получил MP4-клип.

### VOD

- Источник видео: Twitch VOD URL или локальный видеофайл.
- Источник чата: загруженный лог или ранее сохранённый LIVE лог.
- Поддерживаются TwitchDownloader JSON/JSON.GZ, JSONL, CSV, TXT, SRT (смотрите парсер в коде для точных вариантов).
- Таймкоды чата должны соответствовать началу и длительности того же VOD.
- Алгоритм `rank_twitch_chat_moments()` ранжирует всплески чата.
- Результаты экспортируются в MP4, с настройкой длины, числа клипов и аспектного соотношения.
- История сессий и клипы хранятся локально.

Для старых VOD пользователь использовал TwitchDownloader GUI v1.56.5; в нём выбирал Chat Download, вставлял VOD URL, формат JSON и скачивал чат. Ссылка релизов: https://github.com/lay295/TwitchDownloader/releases.

## 6. Локальное хранение данных

`ROOT = Path(__file__).parent`.

`.gitignore` намеренно исключает содержимое `data/`, `uploads/`, `outputs/`, `.venv/` и файлы секретов. Это предотвращает публикацию личных видео/проектов и токенов. Для переноса данных между ПК скопировать соответствующие локальные папки отдельно после остановки приложения. Не загружать пользовательские данные в GitHub без прямого согласия.

## 7. Секреты, ключи, Twitch OAuth

- Никогда не записывать в код, Markdown, скриншоты, Git commit или GitHub: OpenAI API key, Twitch OAuth token, пароли и прочие credentials.
- OAuth token пользователя должен иметь `chat:read` для чтения чата. Для native clip action дополнительно `clips:edit`.
- Twitch Client ID должен соответствовать приложению, для которого выдан токен.
- В UI поля token/key имеют тип password. Не меняй это на обычный открытый text input.
- Если пользователь случайно показал или закоммитил реальный токен, посоветуй отозвать/перевыпустить его в Twitch Developer Console. Не копируй токен в документацию.
- OpenAI API тарифицируется отдельно от ChatGPT подписки. Не обещай, что Plus/Pro/Go включает API-кредиты.
- В текущем коде API key заявлен как хранимый только в Streamlit session state; перед изменением механизма конфигурации внимательно проверь, чтобы он не попадал в лог/проект.

## 8. История пользовательских проблем и важные UX требования

- Ранее установщик v17 однажды некорректно выполнился: Windows CMD показывал `'1' is not recognized...` и путь к Python-файлу был интерпретирован с ошибками. Если меняешь `.bat`, внимательно проверяй quoting, `cd /d`, пути с пробелами, `chcp 65001`, `if errorlevel`, не запускай текстовый README как BAT.
- Пользователь видел чёрное окно CMD, которое закрывалось после нажатия кнопок/ошибки. При диагностике проси скриншот ошибки до закрытия или используй `pause` на ветках ошибки. Не обещай, что чёрное окно само по себе означает сбой: Streamlit запускается из консоли.
- В Twitch Clipper пользователь настроил OAuth: логин Twitch `subsideics`, Client ID и OAuth token были введены в поля UI. Не повторяй и не запрашивай раскрыть значения на скриншотах. Не сохраняй их в файлах репозитория.
- У пользователя мониторинг Twitch успешно подключился: на скриншоте было «Подключено — ждем сообщения в чате», канал `shadowkewk`, получено 37 сообщений, отображались сообщения и предупреждение о всплеске (27 сообщений за 30 секунд, 12 за 10 секунд). Значит в той конкретной сессии LIVE чат-соединение сработало.
- Объяснено, что чат-мониторинг не пишет само видео; после стрима нужен VOD плюс соответствующий чат-лог, чтобы делать MP4.
- Пользователь скачал TwitchDownloader GUI v1.56.5 Windows x64 и видел его окно с кнопками VOD Download / Clip Download / Chat Download / Chat Updater / Chat Render. Для экспорта старого VOD чата использовали Chat Download и JSON.
- Пользователь создал Twitch Developer application. Было сообщение о необходимости 2FA; после включения/повторной попытки приложение создалось. Client ID скопирован и вставлен в CLIP AI. Точный Client ID и токен в документации не указывать.
- При создании приложения Twitch redirect URL `http://localhost:3000` был введён, хотя форма показывала HTTPS validation в одной попытке; в итоге пользователь создал приложение с localhost redirect URL. Не меняй настройки OAuth без необходимости; если потребуется OAuth callback flow, проверь актуальные требования Twitch и совпадение redirect URL.
- Пользователь просил, чтобы UI был красивым, читаемым и удобным: статусы, полосы прогресса, шаги и сообщения должны выглядеть опрятно, без наложений и непонятных технических ошибок. Сохраняй Premium Violet стиль и русскоязычный интерфейс.

## 9. GitHub handoff и работа брата

Задача текущего handoff: дать брату пользователя возможность открыть репозиторий, передать этот `AI_CONTEXT.md` своему ChatGPT, разобраться в назначении приложения и адаптировать интерфейс/функции под себя.

Рекомендованный рабочий процесс:

1. Пользователь загружает весь репозиторий в GitHub (не только `app.py`).
2. Даёт брату доступ как Collaborator.
3. Брат клонирует репозиторий и открывает `AI_CONTEXT.md` вместе с `app.py` в своём ChatGPT.
4. ChatGPT должен сначала изучить текущий `app.py`, `README.md`, `requirements.txt` и этот handoff, а не генерировать новый проект с нуля.
5. Брат делает изменения в отдельной ветке и Pull Request.
6. Не коммитить `.venv`, `data`, `uploads`, `outputs`, API keys и Twitch OAuth.

Пример запроса брату для ChatGPT:

> Изучи `AI_CONTEXT.md` и `README.md`, затем внимательно проанализируй текущий `app.py`. Это существующий локальный Streamlit проект CLIP AI Studio v21. Не переписывай приложение с нуля. Сначала кратко опиши архитектуру и точки, которые нужно изменить для моей задачи. Затем внеси только согласованные изменения, сохрани все существующие функции, данные, Premium Violet стиль и Twitch Clipper. Проверь `python -m py_compile app.py`, обнови README/requirements при необходимости и дай список изменений и способ запуска.

## 10. Правила дальнейшей разработки

1. Всегда сначала прочитать актуальный код, не полагаться только на этот контекст.
2. Не удалять существующие модули и пользовательские данные ради упрощения.
3. Делать изменения минимальными и совместимыми с уже существующими project JSON/session state ключами.
4. Сохранять русский язык UI, Premium Violet / By Senya branding, адаптивность и понятные статусы.
5. Для тяжёлых операций использовать прогресс и понятные сообщения ошибок; не оставлять бесконечные индикаторы без объяснения.
6. После изменений проверять как минимум `python -m py_compile app.py`; если возможно, проверить установку зависимостей и запуск Streamlit.
7. Проверять архив: он должен содержать актуальные `app.py`, `requirements.txt`, launcher и документацию.
8. Не говорить, что LIVE пишет видео или что чат-всплеск гарантирует эпичность/вирусность. Это эвристический сигнал; финальный клип нужно просмотреть.
9. Не утверждать, что приложение публично доступно через интернет: пока оно локальное.
10. Учитывать лицензии и права на исходное видео, музыку, чат и клипы; обрабатывать только материалы, на которые у пользователя есть разрешение.

## 11. Что не следует предполагать

- Неизвестно, настроен ли у пользователя Git на компьютере брата; GitHub upload через веб-интерфейс тоже возможен.
- Неизвестно, какие модели OpenAI доступны именно его API-аккаунту. Проверяй модель через актуальную документацию/доступ API, не обещай доступ по названию из интерфейса.
- Неизвестно, есть ли у второго компьютера GPU. Текущая конфигурация рассчитана на CPU и может работать медленно; оптимизация под GPU — отдельная задача.
- Неизвестно, какие папки с локальными данными пользователь захочет переносить. Не включай их в публичный архив без явного согласия.
- Файл `AI_CONTEXT.md` описывает контекст текущего диалога и историю проекта, но не содержит буквально каждое сообщение или все изображения. Он специально собран как рабочая передача решений, архитектуры, ограничений и проблем.
